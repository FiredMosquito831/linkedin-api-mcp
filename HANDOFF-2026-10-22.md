## Key technical findings (do not re-derive)

- LinkedIn **obfuscates class names** (`kxh4j`). Class-based selectors are dead. Use `data-testid`, `componentkey`, `data-job-id`, `role`, `aria-label`.
- Feed list mixes posts with suggested people and ads. Only list items containing `[aria-label^="Reaction button state"]` are posts.
- Some live controls are **excluded from the accessibility tree**: `getByRole('button', {name:'Follow'})` = 0 while `getByLabel('Follow')` = 1. Resolution now tries role, then label, then the attribute selector.
- Controls can be **absent briefly after navigation**; `uniqueControl` waits for a candidate before declaring it missing.
- Connections route is `/mynetwork/invite-connect/connections/`.
- The app shell returns **intermittent 404** for routes it still renders; accepted only when `main`/`role=main` attaches.
- A challenge **before** dispatch is `AUTH_REQUIRED` (exit 3), not `completionUnknown` (exit 8). The adapter's own verdict now wins over the service fallback.
- Profile edit entry is `<a aria-label="Edit profile">`, not `role=button "Edit professional profile"`.
- Inbox rows are the thread **links** themselves; the "new message" stub must be excluded.
